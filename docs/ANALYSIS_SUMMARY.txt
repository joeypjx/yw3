3. 架构亮点
================================================================================

3.1 DDD 实践
  - 富领域对象: AlertRule, AlertEvent (包含业务规则)
  - 仓储模式: 使用接口隔离数据访问
  - 领域服务: AlertExpressionEvaluationService 处理复杂逻辑
  - 值对象: AlertExpression, EvaluationResult

3.2 依赖倒置原则
  - 定义清晰的仓储接口:
    * IAlertRuleRepository
    * IMetricRepository
    * IAlertEventRepository
    * IServerNodeRepository
  - 当前使用 Mock 实现便于开发
  - 易于替换为 PostgreSQL/InfluxDB 实现

3.3 清晰的分层结构
  - Presentation 层: 只负责 HTTP 路由和序列化
  - Application 层: 编排业务用例
  - Domain 层: 核心业务逻辑
  - Infrastructure 层: 数据持久化和外部集成
  
  依赖方向: Presentation → Application → Domain ← Infrastructure

3.4 复杂告警规则支持
  - 多条件表达式: cpu.usage_percent > 80 AND memory.usage_percent > 90
  - 持续时间检查: 条件需持续1分钟才触发
  - 数据新鲜度检查: 确保数据质量
  - 时间序列计算: 支持复杂的时序数据分析

3.5 告警事件生命周期管理
  - 状态机: FIRING → ACKNOWLEDGED → RESOLVED
  - 不可逆: 一旦解决就不能回复
  - 业务规则强制: 通过异常保证合法性

4. 核心业务流程
================================================================================

4.1 数据上报流程 (每30秒)
  1. Agent Collector 采集系统指标
  2. Formatter 将数据转为 JSON
  3. Reporter POST /api/resource 发送数据
  4. Server HttpServer 接收请求
  5. IngestionService 处理:
     - RegisterOrUpdateNode() 更新节点信息
     - SaveMetricSnapshot() 保存指标数据

4.2 告警评估流程 (每30秒)
  1. AlertingOrchestratorService 定时触发
  2. 遍历所有启用的告警规则
  3. 对每个规则和节点:
     - 查询最近的指标数据
     - 调用 AlertRule.evaluate() 评估
     - AlertExpressionEvaluationService 计算表达式
     - 根据结果生成或更新 AlertEvent
  4. 保存到 AlertEventRepository

4.3 告警事件生命周期
  FIRING (触发) → acknowledge() → ACKNOWLEDGED (已认知)
                  ↓
                resolve() → RESOLVED (已解决)

5. REST API 概览
================================================================================

数据接收:
  POST /api/heartbeat              # Agent 心跳
  POST /api/resource               # Agent 上报指标

告警规则管理:
  POST   /api/alert-rules          # 创建规则
  GET    /api/alert-rules          # 获取所有规则
  GET    /api/alert-rules/{id}     # 获取单个规则
  PUT    /api/alert-rules/{id}     # 更新规则
  DELETE /api/alert-rules/{id}     # 删除规则
  GET    /api/alert-rules/active   # 获取启用的规则
  POST   /api/alert-rules/{id}/enable
  POST   /api/alert-rules/{id}/disable

告警事件管理:
  GET    /api/alert-events         # 所有事件
  GET    /api/alert-events/{id}    # 单个事件
  GET    /api/alert-events/active  # 活跃事件
  GET    /api/alert-events/status/{status}  # 按状态筛选
  POST   /api/alert-events/{id}/acknowledge # 认知事件
  POST   /api/alert-events/{id}/resolve     # 解决事件

数据查询:
  GET    /api/nodes                # 所有节点
  GET    /api/nodes/{nodeId}       # 单个节点
  GET    /api/nodes/{nodeId}/metrics?recentSeconds=300
