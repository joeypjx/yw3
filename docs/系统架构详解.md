## 4. 告警事件生命周期状态机

```
┌────────────────────────────────────────────────────┐
│        AlertEvent 状态机                            │
└────────────────────────────────────────────────────┘

                  创建
                   │
                   ↓
        ┌──────────────────┐
        │     FIRING       │  (告警触发中)
        └────┬──────┬──────┘
             │      │
             │      │ acknowledge()
             │      ↓
             │  ┌──────────────────┐
             │  │  ACKNOWLEDGED    │  (已认知)
             │  └────┬──────┬──────┘
             │       │      │
             │       │      │
    resolve()│       │      │ resolve()
             │       │      │
             ↓       ↓      ↓
        ┌──────────────────────┐
        │     RESOLVED         │  (已解决)
        └──────────────────────┘

业务规则:
- AlertEvent 只能由 AlertingOrchestratorService 创建
- 从 FIRING 状态:
  ├─ 可以 acknowledge() → ACKNOWLEDGED
  └─ 可以 resolve() → RESOLVED

- 从 ACKNOWLEDGED 状态:
  └─ 可以 resolve() → RESOLVED

- 从 RESOLVED 状态:
  └─ 不可变更 (终态)

- resolve() 操作是幂等的
```

## 7. 告警触发和事件生成示例

```
┌────────────────────────────────────────────────────┐
│  告警规则触发流程示例                               │
└────────────────────────────────────────────────────┘

配置的规则:
  AlertRule ID: 1
  Name: "High CPU Usage"
  Expression: cpu.usage_percent > 80.0 for 1m
  Severity: WARNING
  Enabled: true

实时场景:
  T0 (时间 0s):
    CPU 使用率: 75%
    → 评估: OK (75 < 80)

  T1 (时间 30s):
    CPU 使用率: 82%
    → 评估: OK (持续时间 < 1m 要求)

  T2 (时间 60s):
    CPU 使用率: 83%
    → 评估: TRIGGER (连续1分钟 > 80)
    → 创建 AlertEvent
       {
         eventId: 1,
         ruleId: 1,
         nodeId: "node-001",
         status: FIRING,
         severity: WARNING,
         startAt: T2,
         triggeredValue: 83.0
       }
    → 保存到 AlertEventRepository

  T3 (时间 90s):
    CPU 使用率: 81%
    → 评估: TRIGGER (仍然 > 80)
    → AlertEvent 已存在, 状态无变化
    → 无新操作

  T4 (时间 120s):
    CPU 使用率: 78%
    → 评估: RESOLVED (不再 > 80)
    → 更新 AlertEvent
       {
         status: RESOLVED,
         endAt: T4
       }
    → 保存到 AlertEventRepository

前端显示:
  仪表板统计:
  ✓ 触发的规则: 1
  ✓ 活跃事件: 0 (已解决)
  ✓ 告警历史: 显示该事件
```
