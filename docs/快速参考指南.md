## 5. 关键类和接口

### 领域实体
```cpp
// 规则实体 - 支持多条件告警
class AlertRule {
    int32_t ruleId;
    std::string alertName;
    AlertExpression expression;  // 复杂表达式
    std::string severity;
    bool isEnabled;
    EvaluationResult evaluate(...);
};

// 告警事件 - 状态机管理
class AlertEvent {
    enum Status { FIRING, ACKNOWLEDGED, RESOLVED };
    void acknowledge(const std::string& operatorId);
    void resolve();
};

// 指标快照 - 时间序列数据
class MetricSnapshot {
    std::string nodeId;
    uint64_t timestamp;
    std::map<std::string, double> metrics;
    std::map<std::string, std::string> tags;
};

// 节点 - 被监控的服务器
class ServerNode {
    std::string nodeId;
    std::string hostname;
    std::string status;
};
```

### 仓储接口 (依赖倒置)
```cpp
class IAlertRuleRepository {
    virtual void save(const AlertRule& rule) = 0;
    virtual std::optional<AlertRule> findById(int32_t id) = 0;
    virtual std::vector<AlertRule> findAllActive() = 0;
};

class IMetricRepository {
    virtual void save(const MetricSnapshot& snapshot) = 0;
    virtual std::vector<MetricSnapshot> findRecent(
        const std::string& nodeId, int32_t seconds) = 0;
};
```

## 6. 业务流程速览

### Agent数据上报流程
```
Agent Collector 采集指标
   ↓
Formatter 格式化为JSON
   ↓
Reporter HTTP POST /api/resource
   ↓
Server IngestionService 接收
   ↓
保存到 MetricRepository
```

### 告警评估流程
```
AlertingOrchestratorService 定时触发 (30秒)
   ↓
获取所有启用的规则
   ↓
FOR EACH 规则:
   获取最近的指标数据
   调用 AlertRule.evaluate()
   检查表达式是否满足
   ↓
根据结果:
   如果 TRIGGER → 创建新的 AlertEvent(FIRING)
   如果 RESOLVED → 更新现有 AlertEvent(RESOLVED)
   如果 OK → 无操作
```

### 告警事件生命周期
```
创建 FIRING (触发)
   ↓
用户 acknowledge() → ACKNOWLEDGED
   ↓
自动或手动 resolve() → RESOLVED (终态)
```

## 9. 常见问题排查

### Server启动失败
```bash
# 检查端口是否被占用
lsof -i :18888
# 杀死占用进程
kill -9 <PID>
```

### Frontend连接Server失败
```
错误: "连接错误: Connection refused"
解决: 确保Server已启动，地址正确
monitoring_dashboard.py 中: SERVER_BASE_URL = "http://localhost:18888"
```

### Agent无法连接Server
```bash
# 检查网络连接
ping localhost
# 检查防火墙
sudo lsof -i :18888
```

### 没有告警触发
1. 确保规则已启用
2. 确保指标数据足够新鲜
3. 检查告警条件是否真的满足
4. 查看Server日志

## 11. 开发工作流

### 添加新的告警规则类型
1. 编辑 `domain/entities/alert_rule.hpp`
2. 在 `AlertExpression` 中定义新的条件类型
3. 更新 `domain/services/alert_expression_evaluation_service.cpp`
4. 在应用层添加单元测试
5. 更新 `ALERT_EVENTS_API.md` 文档

### 集成新的数据源
1. 在 `agent/collector/collector.cpp` 中添加收集逻辑
2. 更新 `domain/entities/metric_snapshot.hpp` 添加新指标
3. 修改 `infrastructure/repositories/` 实现以支持新指标
4. 更新前端显示模板

### 添加新的通知方式
1. 创建 `infrastructure/notifiers/xxx_notification_service.cpp`
2. 实现 `INotificationService` 接口
3. 在 `main.cpp` 的依赖注入中替换 Mock 实现
4. 添加配置参数

## 14. 快速问题排查流程

```
问题: 告警没有触发
  ↓
检查 Server 是否运行
  ├─ 否 → 启动 Server: ./build/monitoring_server
  └─ 是 → 继续
  ↓
检查 Agent 是否连接
  ├─ 查看 Server 日志输出
  ├─ 否 → 启动 Agent: ./build/monitoring_agent localhost 18888
  └─ 是 → 继续
  ↓
检查指标数据是否更新
  ├─ GET /api/nodes/{nodeId}/metrics?recentSeconds=60
  ├─ 无数据 → 检查 Agent 采集是否正常
  └─ 有数据 → 继续
  ↓
检查规则是否启用
  ├─ GET /api/alert-rules/active
  ├─ 规则不在列表中 → 使用 POST /api/alert-rules 创建
  └─ 规则在列表中 → 继续
  ↓
检查规则条件是否满足
  ├─ 获取最近的指标
  ├─ 对比规则阈值
  ├─ 条件不满足 → 等待或调整规则
  └─ 条件满足 → 检查日志获取更多信息
```
